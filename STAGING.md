# Private staging deployment

Use a Linux server with Docker Compose and a DNS hostname pointing to the server. Allow TCP 80 and 443 for Caddy and restrict SSH to your administrator IP. PostgreSQL and FastAPI are reachable only within the Compose network.

1. Unpack the clean source bundle. Copy `staging.env.example` to `.env.staging` and set file permissions to owner-only. Set `JOBPILOT_DOMAIN` to the DNS hostname and `STAGING_ALLOWED_IP` to your public IP or a trusted CIDR. Do not set the allowlist to a public wildcard. Generate separate secrets with `openssl rand -hex 32` for `POSTGRES_PASSWORD` and `SECRET_KEY`. The database password must be URL-safe because it is part of the database URL.
2. Start staging with `docker compose --env-file .env.staging -f compose.staging.yaml up -d --build`. The backend applies Alembic migrations at startup. Check `docker compose --env-file .env.staging -f compose.staging.yaml logs backend web` and open the HTTPS hostname from an allowed IP. Caddy forwards `/api/v1/*` and serves the frontend for direct visits and page reloads.
3. For a smoke test, create a staging account and use a synthetic resume. Verify login, reload on a protected route, and resume extraction after supplying your Gemini key. Confirm the site returns 403 from an IP outside the allowlist. All registered staging accounts share the HR directory, so keep access limited to trusted users.
4. To keep existing accounts, profiles, contacts, and sources, back up the local PostgreSQL database and restore it into a fresh staging database before starting the backend. Transfer private files separately through a secure channel and verify file checksums. Put resumes into the private storage volume, then update their stored paths to the corresponding Linux files under `/app/private_storage/resumes`. Check queued outreach attachment paths and preserve the existing mail encryption key if migrating a connected sender. Keep the mail worker disabled until those paths and credentials have been verified.
5. Create a fresh Telegram session on the server with `docker compose --env-file .env.staging -f compose.staging.yaml exec backend python -m app.collectors.telegram --login` after setting the Telegram API credentials. If the previous session was shared through Git history, revoke it through Telegram's Devices settings. Verify the new session can read the configured channels before setting `COLLECTION_ENABLED=true` and recreating the backend container. Verify the next 8:00 AM IST run in the app with the laptop off.

The Docker volumes hold the database, private uploads, Telegram session, and HTTPS certificates. Back up important data separately before replacing any volume. The staging configuration expects Caddy to receive client traffic directly so its IP allowlist can use the connection address.
